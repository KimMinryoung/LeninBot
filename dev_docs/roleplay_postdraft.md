# 역할극 초안 사후 정산

구현: `runtime_tools/roleplay_turn.py`, `telegram/roleplay_bot.py`.
`roleplay_scene_consistency.enabled=true`로 서술 검토를 활성화한다.

## 처리 순서

1. 사용자 원문과 직전 문맥에서 LLM `roleplay_time_authorization`이 실행/상담/계획/정정/초기화(mode), 세션(span), 날짜 전환(transition), 시간 허가(time_scope), 선택된 명시 기간(duration_minutes), 수치 정정의 대상·최종값(corrections), 예약할 사건 제목(appointment)을 한 번에 판정한다.
2. 기존 연기 모델이 초안을 쓴다. SQLite 임시 복사본에서 도구가 작동하며 인물·메모·장면 변경은 아직 실저장되지 않는다.
3. scene 모드에서만 JEV가 초안의 사건·활동·부상·장면 끝 인물 출입을 분류한다. 다른 모드는 입력 판정의 작업과 인자를 코드가 사용한다.
4. 코드가 사건 효과와 시간 적분을 계산한다. 기간이 명시되지 않으면 기존 시간 추정 LLM이 초안 소요 분만 제안한다.
5. scene 모드에서 Jev가 초안과 정산 후 질적 상태·이번에 변경된 기록의 명시적 모순을 먼저 선별한다. 확신 있는 무모순 판정만 상세 검토를 생략하고, 나머지는 기존 서술 검토 모델이 지적을 남긴다. 사건 분류나 수치 계산 권한은 없고 지적 자체가 초안을 막지는 않는다.
6. 동일 초안과 상태·인물·메모를 revision/기록 충돌 검사 후 한 트랜잭션으로 확정한다. 그 뒤 답변을 저장·전송한다.

상세 서술 검토는 기존 연기 모델과 같은 `deepseek_anthropic` 제공자·endpoint인지 코드로 검사한다.
숫자 계수나 전체 메모 스냅샷은 전달하지 않는다. 등록된 호출 이름은 `roleplay_scene_consistency`다.
상세 검토 비활성화·잘못된 JSON·잘린 응답·통신 오류는 검토 미완료로 기록하고 이미 정산된 턴은 확정한다. approved=null, status=unavailable로 남기며 승인으로 위장하지 않는다.

비용 선별은 `runtime_tools/roleplay_review.py`의 `roleplay_consistency_screen`(TypeSafe Jev)이다.
`roleplay_scene_consistency.jev_precheck=true`일 때 같은 최소 문맥으로 consistent/contradiction/uncertain을 한 번 묻는다.
consistent 신뢰도 0.9 이상만 생성 검토를 생략한다. 문턱값은 0.9~1 범위에서 높일 수 있다.
저신뢰·모순·불확실·판정 장애·선별 비활성화는 기존 상세 검토로 진행하며 Jev 선별은 재시도하지 않는다.
선별 답변·모델·비용·지연과 실제 검토 경로를 `verdict.final_review`에 보존한다.
`jev_precheck=false`로 기존 매 턴 상세 검토로 되돌릴 수 있다. 코드 적용에는 봇 재시작이 필요하다.
모의 응답 테스트는 호출 절약·폴백·문맥 제한을 검증하며, 실제 장면 정확도와 운영 비용 절감률은 별도 측정 대상이다.

## 입력 모드별 세 처리 경로

규칙 버전 9에서 입력 모드는 5개를 유지하며 `prepare`는 다음처럼 분기한다.

| 경로 | 모드 | 처리 |
|---|---|---|
| 장면 진행 | scene | Jev 사건 판정, 필요 시 소요 추정, 사건·시간 정산, 서술 검토 |
| 상담 답변 | discussion | 사건·수치·시간 정산 없이 답변; 기존 질적 서술·메모 저장 계약 유지 |
| 명시적 상태 변경 | correction/reset/plan | LLM이 확정한 정정값/초기화 모드/예약을 코드로 검증·적용 |

장면 외 모드는 Jev 사건 분류와 소요 시간 추정, Jev 서술 선별과 상세 장면 검토를 모두 생략한다.
따라서 해당 모델 장애가 이미 해석된 상담·정정·초기화·예약을 막지 않는다. 입력 판정 LLM과 답변 생성은 계속 필요하다.
감사에는 `classification_skipped=non_scene`, 빈 `calls`, 분류 비용/지연 0을 남긴다(전체 턴 비용 0이라는 뜻이 아니다).
`final_review`는 `approved=null/status=skipped/reason=non_scene`이며 검사하지 않은 답변을 승인으로 기록하지 않는다.
장면 모드의 실제 섭취와 일정에 따른 사건 정산은 기존대로 유지한다.

plan의 `appointment`는 `{"title":"방문"}` 같은 객체이며 `duration_minutes`가 현재부터 도래까지의 양수 지연(최대 7일)이다.
다른 모드는 appointment=null이다. 제목·지연이 없거나 잘못되면 등록하지 않는다.
Telegram은 원문 숫자를 다시 추출하거나 Jev에게 예약 의도를 재판정시키지 않는다. 원문은 source로, 구조화한 제목은 title로 보존한다.
검증: `tests/test_roleplay_mode_routes.py`와 `tests/test_roleplay_time.py`.

초안은 최대 2회 작성한다(재작성은 예정 사건 도래로 초안을 끝까지 실행할 수 없을 때와 분류 호출 실패 때). 실패한 초안의 도구 변경과 수치 변화는 폐기한다.
이미 확정한 메시지는 `automatic_turns.reply`의 동일 답변을 반환하며 재정산하지 않는다.
구형 캐시에 검토된 답변이 없으면 새 초안을 임의 확정하지 않는다.
SQLite 확정과 PostgreSQL 대화 기록·Telegram 전송은 분산 트랜잭션이 아니다.
전송 실패 후 동일 메시지를 재처리하면 저장된 답변을 재사용하지만, Telegram 전달의 정확히 한 번 보장은 하지 않는다.

## 불확실한 판정의 처리와 확정 한 줄

원칙은 "턴은 반드시 확정된다"이다. 판정이 불확실하면 보수적으로 채우고 확정 한 줄에 표시하며, 플레이어가 대화로 정정한다.

- 허가 판정: LLM이 모호한 시간 지시는 current/none/0으로 반환하도록 지시한다. 잘못된 JSON·라벨·범위·라벨 간 모순·통신 실패는 저장 전 실패로 처리하며 숫자 파싱이나 Jev로 대체하지 않는다.
- 초안 범위 검사는 없다. 초안이 실제로 한 일은 장소 라벨·사건 축·소요 분(페이싱 상한)이 정산하고, 범위 유지는 초안 작성 전
  scene_direction(현재 위치, 종료점, 한두 문단)으로 유도한다.
- 사건 축·강도·활동이 불확실하면 확률 1위 값으로 채운다(`_auto_settle`, 초안당 최대 4회, `player_settled`). 소요 10분 이하 구간의
  활동은 light다. 강도·활동 후보는 최신 유효 확률순이며 이미 선택을 마친 뒤 남은 미확정 항목도 이 분포를 사용한다.
  확률이 없거나 동률이면 강도 moderate, 활동 질문 light, 선택 뒤 남은 긴 구간 활동 rest를 기본값으로 쓴다.
  기본값 적용 후에도 진행 중 가해와 휴식/수면의 충돌을 검사하며 충돌 시 저장하지 않는다.
  확정 한 줄에 "애매해서 자동 처리: 사건=배려·양보"로 남긴다.
- 소요 시간 추정이 한도(10분, 세션 180분, "맘대로 쉬어" 같은 개방형 휴식 180분)를 넘거나 -1이면 한도로 절단한다(`duration_estimate.capped`).
- 서술 검토(`roleplay_scene_consistency`)는 자문이다. 지적은 확정 한 줄에 "서술 검토 지적: …"으로 붙고 초안을 다시 쓰게 하지 않는다.
- `/ask 켜기`(preferences `ask_player`)면 위 자동 처리 대신 버튼으로 묻는다: 초안 본문을 먼저 보여 주고 후보 버튼(`rp:<scope>:<key>:<label>`)과
  "이 초안 버리기"를 보낸다. 고른 라벨을 같은 verdict에 넣어 동일 초안을 정산하며(`prepare(verdict=…)`), 첫 탭이 초안을 선점해 연타를 막는다.
  재시작·다른 메시지 이후의 콜백은 무효 안내만 한다. 소유자 미들웨어는 callback_query에도 적용된다.

확정된 답변 뒤에는 엔진이 믿은 것을 한 줄로 붙인다(`roleplay_turn.feedback_line`: 사건 라벨(여러 축은 "+"로), 소요 분, 시각, 멈춘 사건,
넘긴 것, 거래 정산, 미뤄 둔 반응, 자동 처리 항목, 서술 검토 지적). 수치와 임계값은 넣지 않는다. `/feedback 끄기|켜기`, 기본 켜짐.

그래도 저장되지 않는 턴(허가 판정 호출 실패, 분류 호출 실패, 빈 답변, 내부 오류)은 마지막 초안을 "미확정 초안"으로 보여 준 뒤
"막힌 부분"을 알린다(`_ISSUE_TEXT`로 플레이어용 문구). 그 사용자 메시지는 `history_exclusions`에 넣어 다음 초안의 문맥에서 뺀다
(PostgreSQL 원본 유지). 답하지 못한 지시가 이력에 남으면 다음 초안이 그것들을 한꺼번에 실행하려 든다.

연기 모델의 `roleplay_state(update)`는 서술 필드만 바꾸므로 오래된 expected_revision을 경고와 함께 받아들이고, 알 수 없는 문자열 인자는
reason에 합친다. 수치·구조 인자는 여전히 거절한다.

## 일과·연표 사건에서의 중단

명시적 기간 진행이 등록된 일과나 예정 사건을 지나면 초안 작성 전 scene_direction에 멈출 지점을 알리고(`expected_stop`), 정산은 그 도래 시점까지만
확정한다. 초안 소요 추정으로 진행하는 짧은 행동이 예정 사건에 걸리면 초안을 다시 쓴다. 세부는 [roleplay_game_balance.md](roleplay_game_balance.md).

## 시간과 사건 경계

‘감방으로 보내’는 도착 한 장면이다. 식사·수면·다음 날은 별개 사건이며 scene_direction으로 초안에 지시한다.
통상 단일 행동의 시간 상한은 10분이다. 사용자 지시가 집중 심문·긴 진술 등 한 세션이면 180분까지 허용한다.
이는 자동으로 180분을 더한다는 뜻이 아니다. 시간 허가와 명시 기간의 분 환산은 초안 전 LLM이 맡는다. 코드가 형식·한도·라벨 간 일관성을 검증한다.

저녁/밤의 ‘아침에는 … 재현된다’ 같은 감독 지시는 실행 모드가 확정될 때 다음 아침으로 전환한다.
역사적 참고 날짜는 시뮬레이션 날짜가 아니다. 다음 아침의 시작은 게임 추정 06:00이며 초안 소요 시간을 더한다.
그 사이 생략 구간은 장면 시간에 포함하되 `clock.uncalculated_minutes`로 별도 기록한다.
활동이 확인되지 않으므로 그 구간의 수면 회복·피로·부상 진행 등은 계산하지 않는다.
시각의 certainty는 estimated, elapsed_complete는 false로 유지한다. 하루 안에 도래하는 실제 예정 사건을 건너뛰는 전환은 거절한다. when_alone 연기 신호와 먼 미래 사건은 전환을 막지 않는다.

## 심문 사건

JEV는 pressure 축에서 동일 장면의 가장 구체적인 결과 1건을 선택한다(다른 축은 독립). 다음 세 종류는 강도를 다시 추정하지 않고 보통 강도 세션값을 쓴다.

| 종류 | 실제 결과 | 기본 의지 | 기타 기본 효과 |
|---|---|---:|---|
| interrogation | 집중 심문, 아직 자백·연루 진술 없음 | -2 | 긴장 +4, 피로 +2 |
| coerced_confession | 압박 아래 자기 혐의를 인정 | -4 | 긴장 +4, 굴욕 +5 |
| implicating_others | 타인을 혐의에 연루시키는 진술 | -5 | 긴장 +5, 굴욕 +6 |

세 사건을 동시에 중첩하거나 명단 인원수만큼 반복하지 않는다. 낮은 의지·굴욕 포화 등 기존 밸런스 보정은 유지한다.
예정 사건 `story_events`와 실제 발생한 상태 변화 사건은 별개다.

## 검증

`venv/bin/python -m unittest discover -s tests -p 'test_roleplay*.py'`.
임시 저장 격리, 실패 시 무변경, 원자적 확정, 기록 충돌 롤백, 재시도 중복 방지,
다음 아침의 미상 구간과 실제 심문 구간 분리, 서술 검토의 출력 검사·제공자 경로·최소 전달을 검증한다.

## 의미 판정과 코드 검증의 경계

날짜 전환은 모든 사용자 표현에서 허가 LLM의 transition으로 판정한다. “아침에”로 시작하는 문장도
질문을 생략하거나 next_morning으로 강제하지 않는다. 시간 허가가 불확실하거나 누락되면 time_scope=none이며,
원문에 숫자+기간이 있다는 이유만으로 explicit으로 승격하지 않는다. 숫자 파싱은 허가된 기간의 환산에 쓴다.
재판정 뒤에도 미확정이면 후보 순위는 최초 답변이 아닌 최신 재판정 확률을 사용한다.

시간 판정 구현은 `runtime_tools/roleplay_time.py`다. `roleplay_time_authorization`은 thinking을 끈 DeepSeek 원샷이며
기존 초안 전 Jev 허가 호출을 대체한다. 반환값과 근거·모델·지연은 verdict.authorization에 보존한다.
기간을 명시한 턴은 이 값을 정산에 재사용하고 초안 후 소요 추정 호출을 생략한다.
기간이 없는 턴만 초안 후 소요 추정을 호출하므로 초안이 실제로 실행한 시간을 계산할 수 있다.
명시 기간 합산 정규식은 내부/legacy 호출 호환용으로만 남으며 Telegram의 LLM 허가 값이 항상 우선한다.
수치 정정용 정규식은 제거했다. `corrections`는 correction 모드에서만 비어 있지 않은 객체이며,
다른 모드에서는 `{}`다. 값은 hunger/fatigue/pain/tension/resolve/clarity/humiliation의 최종 절대값(0~100)이다.
부정·옛 값·대안·재수정 중 실제 적용값 선택과 현재 수치를 기준으로 한 상대적 정정은 LLM이 해석한다.
코드는 schema·범위·현재 입력 일치만 검증하고 임의 절단이나 원문 재추출을 하지 않는다.
LLM 장애·잘못된 정정 출력은 저장 전 실패하며 검증은 `tests/test_roleplay_time.py`를 포함한다.

검토 입력에는 정산에서 확정한 사건의 질적 이름(`settled_events`)도 전달한다. 상태·메모는 불완전한 요약이며
미기록 소품·생각·화제는 그 자체로 모순이 아니다. 물 섭취와 허기는 양립할 수 있고, 특정 화제를 망설이는 서술을
새 holdout 등록으로 간주하지 않는다. 지적은 같은 장면 끝에서 양립 불가능한 두 명시적 사실을 한국어로 설명하도록 요청한다.
이는 검토 지침이며 모델 오판을 코드로 완전히 배제하지는 않는다. 과거 턴의 감사 기록은 소급 수정하지 않는다.

시간 허가 호출의 provider 오류는 `TimeAuthorizationUnavailable`로 형식/의미 오류와 구분한다.
Telegram은 이 경우 진행 미저장과 같은 메시지의 재전송을 안내하며 사용자 지시를 구체화하라고 요구하지 않는다.
SDK 재시도 후 실패한 요청을 봇에서 무한 재시도하거나 다른 제공자로 자동 전송하지 않는다.

연기 신호(`when_alone`)가 ready여도 `story_interrupt`에는 포함하지 않는다. 경과 후보뿐 아니라
정산 끝의 ready 목록도 실제 시계 차단 사건만 사용한다. 따라서 혼자 있는 장면의 미뤄 둔 반응은
시간 진행·초안 확정·다음 날 전환을 반복 차단하지 않는다. 보조 검토의 ValueError는 prepare에서
검토 미완료로 처리하며 revision 충돌·원자적 저장·실제 예정 사건 경계는 계속 검증한다.
